# 영어체험센터 시간표 작성기

**https://timetable-chi-ten.vercel.app**

강사·프로그램·시수·회피 시간을 입력하면 **체험반별 시간표를 자동으로 배치**하는 웹앱.
체험존이 같은 교시에 겹치지 않도록 잡아 주는 것이 핵심이다.
백엔드가 없고, 입력한 내용은 브라우저(localStorage)에만 남는다.

시간표를 만드는 길은 셋이고, 어느 쪽으로 만들었든 그다음은 똑같다.

| | 어떻게 |
| --- | --- |
| 자동 배치 | 입력해 둔 프로그램 배정으로 새로 짠다 |
| 엑셀 올리기 | **이미 쓰고 있는 시간표**를 그대로 올린다 |
| 직접 입력 | 빈 격자에서 칸을 하나씩 채운다 |

만들어진 시간표는 **손으로 고칠 수 있고**(칸을 끌어다 놓거나 눌러서 편집),
**회차마다 담당 강사만 미는 로테이션**을 입혀 볼 수 있다.

상주형(캠프반이 주 5일 머무는 구조)과 방문형(학급이 몇 교시만 다녀가는 구조) 둘 다 쓸 수 있다.
방문형이면 빈 칸이 많이 남는데, 그건 경고 한 줄로만 알리고 배치는 그대로 진행한다.

## 용어

화면 용어와 코드의 타입 이름은 다음과 같이 대응한다.

| 화면 | 타입 | 뜻 |
| --- | --- | --- |
| 체험반 | `Klass` | 시간표 한 장이 만들어지는 단위. 캠프반이거나 방문 학급 |
| 체험존 | `Room` | 같은 교시에 한 팀만 들어갈 수 있는 공간. 보통 여기가 병목 |
| 강사 | `Teacher` | 원어민·한국인 강사 |
| 프로그램 배정 | `Course` | 한 강사가 한 프로그램을 여러 체험반에 맡는 단위 |

## 입력

| 탭 | 내용 |
| --- | --- |
| 운영 시간 | 운영 요일, 1교시~마지막 교시의 시작·종료 시각, 점심·쉬는시간 칸. 기본값은 09:00 시작 40분 6교시 |
| 체험반·체험존 | 체험반 목록(`A반~F반`, `1반~6반`, `3-1~3-6` 일괄 생성), 체험존(자주 쓰는 존은 한 번에 추가) |
| 강사 | 강사 목록(여러 명 붙여넣기), 강사별 회피 요일·교시 격자 |
| 프로그램 배정 | 강사 × 프로그램 × 체험반 × 주당 시수 × 연속 2교시 횟수 × 체험존 |
| 로테이션 | 같이 도는 강사를 순서대로 묶은 조, 회차(9월·10월…) 목록 |

배정 탭 아래에 **체험존 사용률** 막대가 있다. 존 하나가 쓸 수 있는 칸은 주당 `교시 × 요일`뿐이라,
여기가 100%에 가까워지면 배치가 급격히 어려워진다. 85%를 넘으면 미리 경고한다.

## 이미 있는 시간표 올리기

`[시간표]` 탭의 **엑셀로 이미 짜인 시간표 올리기**에서 `.xlsx` 또는 `.csv` 를 올린다.
두 가지 모양을 읽는다.

- **목록형** — 한 줄이 한 칸. `체험반 | 요일 | 교시 | 프로그램 | 강사 | 체험존 | 연속`
  연속 2교시는 두 줄로 적고 `연속` 칸에 `블록`이라고 쓴다.
  **[양식 받기]** 로 지금 입력값이 예시로 채워진 빈 서식을 받을 수 있다.
- **시간표형** — 이 앱이 내보낸 체험반별 시트 그대로. 세로 병합을 연속 2교시로 되살린다.
  내보내기 → 엑셀에서 손보기 → 다시 올리기가 그대로 왕복한다.

체험반·강사·체험존은 이름이 처음 나오면 자동으로 만든다.
요일과 교시는 자리(index)가 곧 뜻이라 함부로 늘리지 않는다 — 모르는 값이면 건너뛰고 몇 줄인지 알린다.

올리기 전에 몇 칸을 읽었고 무엇이 새로 생기는지 먼저 보여 주고, **바꾸기**와 **기존에 합치기** 중 고르게 한다.
(합칠 때 같은 반의 같은 자리는 올린 쪽이 이긴다.)

읽기도 의존성 없이 한다 — `src/xlsxRead.ts` 가 zip 을 직접 뜯고, 압축 해제만 브라우저·Node 에
이미 있는 `DecompressionStream("deflate-raw")` 에 맡긴다.

## 배치 후 수정

`[시간표 수정]` 을 켜면 그 자리에서 고칠 수 있다.

- **끌어다 놓기** — 칸을 다른 자리로 옮긴다. 이미 찬 자리에 놓으면 두 칸이 맞바뀐다.
- **칸 누르기** — 프로그램·강사·체험존·요일·교시·길이(1교시/연속 2교시)를 고친다. 삭제도 여기서.
- **빈 칸의 `+`** — 새 칸을 만든다. 체험반별 화면이면 그 반으로, 강사별 화면이면 그 강사로 채워진다.

손으로 고치는 중에는 잠깐 겹쳐도 막지 않는다. 대신 겹치는 칸을 표에서 빨갛게 칠하고
목록으로 모아 보여 준다 — 목록의 항목을 누르면 그 칸이 바로 편집 상태가 된다.
잡아 주는 항목은 자동 배치가 0으로 몰아가는 것과 같다(체험반·강사·체험존 겹침, 강사 회피 시간,
점심을 넘는 연속 2교시).

## 강사 로테이션

학기 내내 시간표(무엇을 언제 어디서)는 그대로 두고, 회차마다 담당 강사만 한 칸씩 미는 운영 방식을 그대로 담았다.

> A·B·C 를 이 순서로 묶어 두면 — 9월엔 A가 A표, B가 B표, C가 C표.
> 10월엔 A가 B표, B가 C표, C가 A표.

`[로테이션]` 탭에서 같이 도는 강사를 **순서대로** 조에 넣고(이 순서가 곧 도는 순서), 회차를 만든다.
`3월부터 N개월치 만들기` 를 누르면 조 크기만큼 회차가 한 번에 생긴다.
표로 "이 회차에 누가 누구 시간표를 맡는지" 미리 볼 수 있다.

`[시간표]` 탭 위쪽에서 회차를 고르면 그 회차의 시간표를 보고 그대로 내려받는다.
회차 화면은 기준안에서 파생된 것이라 고칠 수 없다 — 고치려면 `기준안` 으로 돌아간다.
특정 회차를 진짜로 확정하고 싶으면 **[이 회차를 기준안으로 확정]** 으로 굳힐 수 있다.

## 결과 보기

세 축으로 볼 수 있고, 축마다 그대로 내려받을 수 있다.

- **체험반별** — 각 반이 무엇을 언제 하는지
- **강사별** — 강사 개인 일정표
- **체험존별** — 존을 언제 어느 반이 쓰는지 (센터 운영에서 가장 자주 보는 화면)

## 내려받기

- **한 장만** — 구분(체험반/강사/체험존)을 고르고 이름을 입력하면 그 대상만 `.xlsx` 로 받는다.
  일부만 입력해도 되고(`Emma` → `Emma Clark`), 여러 개가 걸리면 후보를 보여준다.
- **전체 한 파일로** — 대상마다 시트 한 장씩 담긴 통합문서 하나
- **회차 전체 한 파일로** — 로테이션 회차 × 대상마다 시트 한 장씩 (`10월 Emma Clark`)
- **전체 목록 CSV** — 한 줄에 한 칸씩 펼친 평면 목록. **업로드 양식과 같은 모양**이라 그대로 다시 올릴 수 있다
- **인쇄 / PDF** — 화면 그대로

엑셀 파일은 연속 2교시 셀 병합, 점심시간 띠, 프로그램별 색, 열 너비까지 표 모양 그대로 들어간다.
`src/xlsx.ts` 가 의존성 없이 xlsx(무압축 zip + XML)를 직접 만든다 — 번들 증가는 gzip 기준 약 4KB.

## 지키는 제약

항상 지켜지는 것 (배치 구조상 깨질 수 없음)

- 한 체험반은 한 교시에 하나의 프로그램만
- 연속 2교시는 붙어 있는 두 교시에만 (점심·쉬는시간 칸을 넘지 않음)

0으로 몰아가는 것

- 한 강사가 같은 교시에 두 체험반에 들어가지 않음
- 강사 회피 시간에는 배정하지 않음
- 같은 체험반의 같은 프로그램은 하루 한 번만 (연속 2교시는 한 번으로 셈)
- 같은 체험존을 같은 교시에 두 반이 쓰지 않음

제한 시간 안에 전부 해소하지 못하면 **충돌 없는 시간표 + 미배치 목록**을 돌려주고,
각 미배치 건마다 "강사 회피 시간 7칸 / 강사가 다른 반 수업 중 5칸" 식으로 막힌 이유를 센다.
남은 것은 `[시간표 수정]` 을 켜고 빈 칸의 `+` 로 직접 밀어 넣으면 된다.

배치가 끝나면 결과는 편집 가능한 목록(`AppData.timetable`)이 된다.
엑셀로 올린 시간표도, 손으로 채운 시간표도 같은 목록에 들어오기 때문에
화면·엑셀 내보내기·로테이션이 어디서 왔는지 따지지 않고 똑같이 동작한다.

## 배치 엔진

`src/solver.ts` — min-conflicts 국소 탐색.

1. 체험반마다 격자에 초기 배치 (연속 2교시 먼저, 같은 프로그램은 다른 요일로)
2. 충돌에 얽힌 프로그램을 골라 자기 반 안의 다른 자리로 이동
   자리 주인은 밀어내고 비용이 가장 낮은 빈칸으로 다시 넣는다(퇴출 이동 = 자리 맞바꾸기)
3. 평지에 갇히면 최선 해로 되돌린 뒤 몇 수를 무작위로 흔들고, 오래 못 벗어나면 완전히 새로 시작
4. 시간이 끝나면 남은 충돌에 가장 많이 얽힌 것부터 빼내어 충돌 0으로 정리

Web Worker(`src/solver.worker.ts`)에서 돌아 화면이 멈추지 않는다.

### 성능 (Node, 참고값)

| 규모 | 결과 |
| --- | --- |
| 6개 캠프반 · 강사 11명 · 존 6개 · 반당 30/30시간 | 0.5s, 완전 배치 |
| 30개 반 · 강사 55명 · 반당 34/35시간 | 15ms, 완전 배치 |
| 30개 반 · 반당 35/35시간(빈칸 0) | 18ms, 완전 배치 |
| 30개 반 · 강사마다 하루 전체 회피 | 1.0s, 완전 배치 |

```bash
npm run sample        # 앱에 든 영어체험센터 예시를 풀고 하드 제약 위반을 직접 검증
npm run stress        # 30개 반 규모 부하 테스트 (HARD=1, EXTRA=1 로 난이도 상향)
npm run xlsx:check    # 생성한 xlsx 가 열리는 파일인지 확인
npm run import:check  # 내보낸 파일을 되읽어 같은 시간표가 나오는지 (CSV·xlsx 왕복), 충돌 검사, 로테이션
npm run render:check  # 시간표·로테이션·편집 화면이 실제로 그려지는지 (서버 렌더링)
```
