# 영어체험센터 시간표 작성기

강사·프로그램·시수·회피 시간을 입력하면 **체험반별 시간표를 자동으로 배치**하는 웹앱.
체험존이 같은 교시에 겹치지 않도록 잡아 주는 것이 핵심이다.
백엔드가 없고, 입력한 내용은 브라우저(localStorage)에만 남는다.

상주형(캠프반이 주 5일 머무는 구조)과 방문형(학급이 몇 교시만 다녀가는 구조) 둘 다 쓸 수 있다.
방문형이면 빈 칸이 많이 남는데, 그건 경고 한 줄로만 알리고 배치는 그대로 진행한다.

## 용어

화면 용어와 코드의 타입 이름은 다음과 같이 대응한다.

| 화면 | 타입 | 뜻 |
| --- | --- | --- |
| 체험반 | `Klass` | 시간표 한 장이 만들어지는 단위. 캠프반이거나 방문 학급 |
| 체험존 | `Room` | 같은 교시에 한 팀만 들어갈 수 있는 공간. 보통 여기가 병목 |
| 강사 | `Teacher` | 원어민·한국인 강사 |
| 프로그램 배정 | `Course` | 한 강사가 한 프로그램을 여러 체험반에 맡는 단위 |

## 입력

| 탭 | 내용 |
| --- | --- |
| 운영 시간 | 운영 요일, 1교시~마지막 교시의 시작·종료 시각, 점심·쉬는시간 칸. 기본값은 09:00 시작 40분 6교시 |
| 체험반·체험존 | 체험반 목록(`A반~F반`, `1반~6반`, `3-1~3-6` 일괄 생성), 체험존(자주 쓰는 존은 한 번에 추가) |
| 강사 | 강사 목록(여러 명 붙여넣기), 강사별 회피 요일·교시 격자 |
| 프로그램 배정 | 강사 × 프로그램 × 체험반 × 주당 시수 × 연속 2교시 횟수 × 체험존 |

배정 탭 아래에 **체험존 사용률** 막대가 있다. 존 하나가 쓸 수 있는 칸은 주당 `교시 × 요일`뿐이라,
여기가 100%에 가까워지면 배치가 급격히 어려워진다. 85%를 넘으면 미리 경고한다.

## 결과 보기

세 축으로 볼 수 있고, 축마다 그대로 내려받을 수 있다.

- **체험반별** — 각 반이 무엇을 언제 하는지
- **강사별** — 강사 개인 일정표
- **체험존별** — 존을 언제 어느 반이 쓰는지 (센터 운영에서 가장 자주 보는 화면)

## 내려받기

- **한 장만** — 구분(체험반/강사/체험존)을 고르고 이름을 입력하면 그 대상만 `.xlsx` 로 받는다.
  일부만 입력해도 되고(`Emma` → `Emma Clark`), 여러 개가 걸리면 후보를 보여준다.
- **전체 한 파일로** — 대상마다 시트 한 장씩 담긴 통합문서 하나
- **전체 목록 CSV** — 배치 결과를 한 줄에 한 칸씩 펼친 평면 목록
- **인쇄 / PDF** — 화면 그대로

엑셀 파일은 연속 2교시 셀 병합, 점심시간 띠, 프로그램별 색, 열 너비까지 표 모양 그대로 들어간다.
`src/xlsx.ts` 가 의존성 없이 xlsx(무압축 zip + XML)를 직접 만든다 — 번들 증가는 gzip 기준 약 4KB.

## 지키는 제약

항상 지켜지는 것 (배치 구조상 깨질 수 없음)

- 한 체험반은 한 교시에 하나의 프로그램만
- 연속 2교시는 붙어 있는 두 교시에만 (점심·쉬는시간 칸을 넘지 않음)

0으로 몰아가는 것

- 한 강사가 같은 교시에 두 체험반에 들어가지 않음
- 강사 회피 시간에는 배정하지 않음
- 같은 체험반의 같은 프로그램은 하루 한 번만 (연속 2교시는 한 번으로 셈)
- 같은 체험존을 같은 교시에 두 반이 쓰지 않음

제한 시간 안에 전부 해소하지 못하면 **충돌 없는 시간표 + 미배치 목록**을 돌려주고,
각 미배치 건마다 "강사 회피 시간 7칸 / 강사가 다른 반 수업 중 5칸" 식으로 막힌 이유를 센다.

## 배치 엔진

`src/solver.ts` — min-conflicts 국소 탐색.

1. 체험반마다 격자에 초기 배치 (연속 2교시 먼저, 같은 프로그램은 다른 요일로)
2. 충돌에 얽힌 프로그램을 골라 자기 반 안의 다른 자리로 이동
   자리 주인은 밀어내고 비용이 가장 낮은 빈칸으로 다시 넣는다(퇴출 이동 = 자리 맞바꾸기)
3. 평지에 갇히면 최선 해로 되돌린 뒤 몇 수를 무작위로 흔들고, 오래 못 벗어나면 완전히 새로 시작
4. 시간이 끝나면 남은 충돌에 가장 많이 얽힌 것부터 빼내어 충돌 0으로 정리

Web Worker(`src/solver.worker.ts`)에서 돌아 화면이 멈추지 않는다.

### 성능 (Node, 참고값)

| 규모 | 결과 |
| --- | --- |
| 6개 캠프반 · 강사 11명 · 존 6개 · 반당 30/30시간 | 0.5s, 완전 배치 |
| 30개 반 · 강사 55명 · 반당 34/35시간 | 15ms, 완전 배치 |
| 30개 반 · 반당 35/35시간(빈칸 0) | 18ms, 완전 배치 |
| 30개 반 · 강사마다 하루 전체 회피 | 1.0s, 완전 배치 |

```bash
npm run sample      # 앱에 든 영어체험센터 예시를 풀고 하드 제약 위반을 직접 검증
npm run stress      # 30개 반 규모 부하 테스트 (HARD=1, EXTRA=1 로 난이도 상향)
npm run xlsx:check  # 생성한 xlsx 가 열리는 파일인지 확인
```
